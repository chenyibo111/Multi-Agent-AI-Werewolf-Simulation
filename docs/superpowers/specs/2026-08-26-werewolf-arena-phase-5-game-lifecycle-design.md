# Werewolf Arena Phase 5 Game Lifecycle Design

**状态：已确认设计，待实施计划**  
**日期：2026-08-26**  
**基线：Phase 4 已合并至 `master`**

## 1. 目标与范围

Phase 5 将当前“可创建并进行一局”的界面扩展为可管理的本地单人游戏闭环。玩家可以从首页恢复当前浏览器已接触过的对局；在死亡后安全旁观；在结局后查看全员身份与完整复盘；并能永久删除不再需要的本地房间。

本阶段继续是“1 名人类玩家 + 5 名 AI”的本地 Web 产品。它不引入账号、跨设备同步、公网部署、多人真人局、移动端专项布局或规则编辑器。

## 2. 产品决策

### 2.1 本地历史的归属

历史列表只显示当前浏览器创建或成功打开过的房间。浏览器保存一份不敏感的本地索引；其中不存会话令牌、角色私密信息、事件内容或完整战报。

房间 ID 不是授权凭证。浏览器每次恢复或刷新条目时，仍由服务端的房间路径 HttpOnly Cookie 校验归属。无 Cookie、Cookie 失效或房间已删除时，前端不显示任何房间细节，只将条目标记为不可访问，允许用户从本地索引移除。

### 2.2 信息可见性

进行中的存活人类玩家继续获得当前安全私密投影。人类死亡后，对局页切换为只读旁观：只接收和渲染公共状态与公共事件，不再显示任何后续角色私密提示、合法目标、行动选项或 AI 私密数据。

只有 `finished` 对局才允许已授权玩家读取完整复盘。复盘包含胜负、全员身份、按顺序的完整权威事件与结果说明；不得包含模型系统 Prompt、原始模型输出、推理草稿、会话令牌或密钥。

### 2.3 删除

房主可在首页或已结束房间中发起删除。前端必须先要求确认；服务端在会话授权成功后事务性删除房间、事件、快照、会话令牌摘要和 AI 调用审计数据。成功后前端移除本地历史条目并导航回首页。不存在、无权或已删除的房间不得泄露额外信息。

## 3. 玩家流程

1. 首页读取浏览器本地历史索引，逐个加载并校验房间；显示“继续对局”和“历史对局”卡片。
2. 创建新局、成功恢复房间或进入已结束房间后，前端更新该房间的本地元数据与最后打开时间。
3. 未结束且人类存活时，保留现有的叙事时间线、私密身份卡和服务端下发的合法行动面板。
4. 人类死亡时，行动面板消失，右侧改为旁观提示和公共存活状态；事件流只展示公共事件。
5. 对局结束时，同一路由展示胜负结果、身份揭晓和完整复盘，并提供“再开一局”“返回历史”“删除对局”。
6. 用户删除或手动移除条目后，本地历史立即更新；删除房间不会影响其他浏览器或其他房间。

## 4. 架构与接口

### 4.1 浏览器本地历史

新增 `RoomHistoryStore`，由 React 首页与房间会话协调层调用。索引的每项最多保存：`room_id`、`last_opened_at`、最后已知的安全 `status`、最后已知 `phase_text` 与显示名。所有字段都被视为不可信的缓存，首次渲染可显示骨架状态，但必须由房间读取接口刷新。

本地索引仅作发现与排序，不能作为服务端批量列房间、续期 Cookie 或跳过房间授权的依据。为避免无账号版本增加设备身份，服务端不新增全局“我的房间”枚举接口。

### 4.2 API 与投影

保留既有单房间读取、命令、继续与 WebSocket 端点。新增：

- `GET /api/rooms/{room_id}/report`：仅完成对局且房间 Cookie/Bearer 令牌通过时返回完整复盘；未结束返回明确的领域错误，未授权按既有授权语义处理。
- `DELETE /api/rooms/{room_id}`：仅已授权房主可删除；成功返回无内容或最小确认载荷，不回传敏感数据。

安全快照投影增加明确的观看模式，例如 `active`、`spectating` 与 `finished`。运行时、REST 与 WebSocket 都复用同一投影规则：死亡人类不再接收私密事件；已结束的完整身份与复盘只由独立 report 端点按规则释放，不能混入实时公共 WebSocket 流。

### 4.3 持久化与删除事务

仓储层增加按房间 ID 的受控删除操作。它在一个事务内清除房间主记录及所有依赖数据，避免留下事件、快照、会话或调用审计孤儿记录。运行时注册表在删除成功后停止或移除对应房间运行时，后续命令和事件连接一致返回房间不存在或授权失败。

已有 SQLite 数据库可通过轻量迁移或兼容读取支持新的投影字段；房间的历史权威事件不改写。旧房间无法形成完整复盘时应返回安全、可诊断的结果，而不是泄露权威状态或使页面崩溃。

## 5. 前端体验

延续“月夜秘仪”视觉体系。历史卡片清楚区分可继续、已结束、不可访问三种状态；不可访问条目不显示角色或事件摘要。删除采用二次确认，避免误删。

对局页继续以中央叙事时间线和右侧状态栏为主体。旁观模式使用明显但不干扰的只读提示；结局区展示胜负、身份卡与复盘，并和进行中时间线视觉区分。所有按钮的可用性仍严格由服务端下发状态决定。

## 6. 测试与验收

后端测试覆盖：

- 删除的级联完整性、重复删除、未授权删除与运行时清理；
- 存活、死亡旁观、结局三种投影的字段与事件可见性；
- 未结束对局不能读取完整复盘；已结束对局可读取脱敏完整复盘；
- 旧房间或缺失新字段的兼容读取与安全降级。

前端测试覆盖：

- 历史索引的写入、刷新、失效与手动移除；
- 删除确认、成功删除后的导航与列表同步；
- 旁观模式不渲染私密面板或行动入口；
- 结局时显示复盘，进行中时不请求或显示完整身份数据。

浏览器端到端测试覆盖：创建房间、发言/投票、死亡后旁观或结局、结局复盘、恢复历史与删除。每个测试都断言页面和网络载荷不包含 `agent_memory`、原始模型文本或其他未授权私密信息。

完成标准：当前浏览器可安全管理自己的本地对局历史；任意对局可继续到胜负；死亡与结局的可见性符合规则；删除不留持久化孤儿数据；不引入账号或跨房间信息泄露。

## 7. 后续阶段

Phase 5 完成后再进入真实模型实战验证与部署准备：受控 smoke 对局、成本/延迟观测、故障排查与部署配置。账号、公网部署、多真人房间、PostgreSQL/Redis、后台规则配置、锦标赛评测与模型/Prompt 对比继续留在后续版本。
