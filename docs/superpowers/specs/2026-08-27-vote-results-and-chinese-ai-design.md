# 投票票型与中文 AI 体验设计

## 目标

在不泄露私密信息或模型原始内容的前提下，公开每轮投票的完整票型；让 AI 玩家在讨论阶段以中文发言，并使用固定、自然且不重复的中文昵称。

## 范围

### 公开票型

当白天投票的所有存活玩家都提交指令时，服务端在清空待处理指令前写入一条公开 `vote_result` 事件。其负载包含按提交顺序排列的投票项：每项只包含 `actor_id` 与 `target_id`；弃权项的 `target_id` 为 `null`。

`vote_result` 无论后续结果是放逐、平票或全员弃权都会产生。现有 `execution`、`vote_tied`、`vote_no_execution` 事件继续分别表达最终结果，保持 API 与复盘兼容。

前端时间线以参与者的 `display_name` 显示票型：投票渲染为“甲 → 乙”，弃权渲染为“甲 → 弃权”。事件负载中的未知 ID 以 ID 兜底，绝不直接展示对象或未允许字段。

### 中文 AI 讨论

AI 的系统提示词改为中文，明确它是在中文狼人杀中发言；`speech` 必须是简短、自然的中文公开发言。仍严格要求模型只输出一个 JSON 对象、使用 `kind`（不是 `action`），并仅采用服务端提供的合法动作与目标。模型输出仍由现有 allowlist 与长度限制把关。

此变更不翻译模型可读的字段名、事件类型或 JSON 契约，以避免破坏当前 DeepSeek JSON 兼容处理；它只改变自然语言指令。

### AI 昵称

标准六人局的五个 AI 座位使用固定昵称：`林小雨`、`周子墨`、`陈星河`、`苏晚`、`顾言`。玩家自身继续显示为“你”。昵称只用于显示层，不改变稳定的内部参与者 ID（`ai-1` 至 `ai-5`）、鉴权或事件引用。

## 数据流与安全边界

```text
投票命令（待结算）
  -> 引擎产生公开 vote_result（仅 actor_id / target_id|null）
  -> 既有投票结果事件
  -> 安全投影
  -> 前端以参与者 display_name 渲染
```

票型本来就是白天公投的公开信息，因此使用 `Visibility.PUBLIC`。模型提示词与模型原始响应仍不会保存或下发；前端未知事件继续使用安全的通用文案。

## 验收标准

1. 唯一放逐、平票、全员弃权三种投票结算都产生一次公开 `vote_result`，其内容完整覆盖存活玩家。
2. 时间线展示玩家昵称与“弃权”，不显示内部 ID（除非遇到不可识别数据时安全兜底）。
3. AI 系统提示词包含中文发言要求，且仍明确要求唯一 JSON、`kind`、合法动作和合法目标。
4. 新建标准对局的五位 AI 玩家显示为约定的中文昵称，稳定 ID 不变。
5. 后端单元测试、前端组件测试与类型检查全部通过。
