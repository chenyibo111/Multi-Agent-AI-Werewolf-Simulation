# Werewolf Arena

面向“1 名人类玩家 + 5 名 AI 玩家”的本地 Web 狼人杀产品。项目提供服务端权威游戏内核、SQLite 房间、会话授权、REST/WebSocket 事件流、兼容 OpenAI Chat Completions 的 AI 自动运行时，以及可直接游玩的 React 浏览器界面。

产品设计见 [Web 产品方案](docs/superpowers/specs/2026-08-25-werewolf-arena-web-design.md)，实施路线见 [Phase 3 计划](docs/superpowers/plans/2026-08-26-werewolf-arena-phase-3-agent-runtime.md)。

## 当前阶段

目前已可在本地浏览器创建标准六人局、与五名 AI 继续对局，并通过 HttpOnly Cookie 保持房间会话。首页仅在当前浏览器保存房间历史；玩家出局后立刻进入安全的全局旁观视角；对局结束后可查看完整复盘。历史卡片可继续或删除对局，删除会同时清理服务端房间与本地记录。

## 玩法说明

标准局共 6 人：你与 5 名 AI。身份为 2 名狼人、1 名预言家、1 名女巫和 2 名平民；创建房间时会随机座位、AI 身份与人类随机身份。若主动选择身份，则只固定你的身份，其余身份仍随机分配。

每回合按以下顺序推进：

1. **狼人行动**：所有存活狼人确定袭击目标。人类是狼人时可以看到同伴，并收到 AI 狼人的私密击杀建议。
2. **预言家查验**：预言家查验一名存活玩家是否为狼人，结果仅预言家可见并可回看。
3. **女巫行动**：女巫得知当晚被袭击者，可使用一次解药救人或一次毒药毒人；行动结果和药剂状态会保留在女巫私密记录中。
4. **白天讨论**：公布昨夜出局者，存活 AI 基于历轮公开发言、夜晚公告和票型进行中文讨论；每天的 AI 发言顺序随机但可恢复。
5. **白天投票**：所有存活玩家投票或弃权，时间线展示具体票型；最高票出局，平票或全员弃权则无人出局。

狼人全部出局则好人阵营获胜；存活狼人数量不少于好人时，狼人阵营获胜。

## 信息与实现机制

- **服务端裁判**：规则结算完全在 Python 服务端完成。浏览器和 AI 都只提交意图，服务端验证目标、身份、阶段和一次性技能，再写入不可变事件流。
- **私密信息隔离**：存活玩家仅获取自己的身份、技能状态与被授权的私密事件；狼人同伴、预言家查验、女巫记录均不会泄露给其他存活玩家。
- **死亡全局旁观**：玩家死亡后立即看到所有角色身份、全部游戏私密事件和后续进程，但仍看不到模型原始请求/输出、思维链、密钥、成本或服务端诊断数据。
- **AI 决策**：每位 AI 接收自己的私密事实、完整且筛选后的公开历史、昵称、座位与存活状态；模型动作仍由服务端 allowlist 约束。自然语言要求使用中文昵称和座位号，而不是内部 `ai-*` ID。
- **可靠运行**：房间状态、事件、会话令牌摘要和 AI 调用指标存入 SQLite；每个房间有异步锁，断线后可从事件序号继续接收 WebSocket 流。

模型运行时采用严格的信息隔离：原始模型输出、思维链和服务端事件不会通过 API 暴露。

后端运行与验证说明见 [backend/README.md](backend/README.md)。

浏览器界面位于 [frontend](frontend)。开发请先启动后端，再在该目录执行 `npm install` 和 `npm run dev`；完整说明见 [后端启动文档](backend/README.md#启动浏览器界面)。
